## 二、MinIO/Redis 版本错配风险提示（本次特有）

本次开发环境曾因 redis/minio 数据被新版镜像写入、与锁定旧镜像不兼容导致容器崩溃循环，已统一为：
- `redis:7-alpine`
- `minio/minio:latest`（2025-08 构建版）

**正式平台升级前请先确认镜像版本**，若与上述不一致，先执行【步骤0】对齐，否则重建后会崩溃。

### 步骤0（条件执行）：对齐 redis/minio 镜像版本

```bash
cd /opt/testplatform
docker ps --format '{{.Names}} {{.Image}} {{.Status}}'
```
- 若 `tp-redis`/`tp-minio` 显示为 `redis:7.2-alpine` / `minio/minio:RELEASE.2024-01-16...` 且状态正常（Up），**不要直接改 compose 升级**，因为现有数据是旧格式。需先确认数据能否被新镜像读取。
- 若处于 `Restarting` 崩溃循环，查看日志：
  ```bash
  docker logs --tail 5 tp-redis     # 出现 "Can't handle RDB format version" 即 redis 版本错配
  docker logs --tail 5 tp-minio     # 出现 "Unknown xl header version" 即 minio 版本错配
  ```
- 处理：将 docker-compose.yml 中 redis 改为 `redis:7-alpine`、minio 改为 `minio/minio:latest`（本仓库已改好），并确认本地已有这两个镜像（无则 `docker pull`），再 `docker compose up -d redis minio`。

## 五、数据库结构变更（alter.sql，先于应用升级执行）

本次 4 个增量脚本（在 `deploy/` 目录，已含幂等保护，按顺序执行）：

```bash
cd /opt/testplatform
set -a; source .env; set +a
MYSQL_ROOT_PASSWORD=$(echo -n "$MYSQL_ROOT_PASSWORD" | tr -d '\r')

for f in alter_schedule.sql alter_attachment.sql alter_mail.sql alter_presales_leader.sql; do
  echo "=== 执行 $f ==="
  docker exec -i tp-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" \
    --default-character-set=utf8mb4 test_platform < deploy/$f
done
```

脚本说明：
| 脚本 | 变更内容 |
|---|---|
| `alter_schedule.sql` | test_application 加排期字段；新增 SCHEDULER 角色并授予 zhangjc/daihw |
| `alter_attachment.sql` | 新建 test_attachment 申请附件表 |
| `alter_mail.sql` | 新建 mail_config、mail_log 表；sys_config 加 platform.base-url |
| `alter_presales_leader.sql` | sys_user_group 加 group_type 字段 |

> 注意：`alter_schedule.sql` 按用户名 `zhangjc`/`daihw` 授权排期员。若正式库用户名不同，请先改 SQL 再执行，或执行后在"用户管理"手动分配"排期员"角色。

**验证变更生效后再进行下一步：**
```bash
docker exec -i tp-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" test_platform -e "
SHOW COLUMNS FROM test_application LIKE 'schedule%';
SHOW TABLES LIKE 'test_attachment';
SHOW TABLES LIKE 'mail%';
SHOW COLUMNS FROM sys_user_group LIKE 'group_type';
SELECT u.username FROM sys_user_role ur JOIN sys_user u ON ur.user_id=u.id JOIN sys_role r ON ur.role_id=r.id WHERE r.role_code='SCHEDULER';"
```
