## 前置检查（重要，避免 MinIO/Redis 版本错配）

升级前确认数据目录与镜像版本一致。本次开发环境曾出现 `redis:7.2-alpine`/`minio RELEASE.2024-01-16` 与数据不兼容导致崩溃循环，已统一为 `redis:7-alpine`、`minio/minio:latest`。

```bash
cd /opt/testplatform
docker ps --format '{{.Names}} {{.Image}} {{.Status}}'
```

若 `tp-redis`/`tp-minio` 处于 `Restarting` 状态，先查看日志确认是否版本错配：
```bash
docker logs --tail 5 tp-redis
docker logs --tail 5 tp-minio
```
出现 `Can't handle RDB format version` 或 `Unknown xl header version` 即版本错配，需使用能读取现有数据的镜像版本（本仓库 docker-compose.yml 已修正）。

## 第 3 步：执行增量 SQL（4 个，按顺序）

```bash
cd /opt/testplatform
PW=$(grep MYSQL_ROOT_PASSWORD .env | cut -d= -f2)

for f in alter_schedule.sql alter_attachment.sql alter_mail.sql alter_presales_leader.sql; do
  echo "=== 执行 $f ==="
  cat deploy/$f | docker exec -i tp-mysql mysql -uroot -p"$PW" --default-character-set=utf8mb4 test_platform
done
```

各脚本作用：
| 脚本 | 内容 |
|---|---|
| `alter_schedule.sql` | test_application 加排期字段；新增 SCHEDULER 角色并授予 zhangjc/daihw |
| `alter_attachment.sql` | 新建 test_attachment 申请附件表 |
| `alter_mail.sql` | 新建 mail_config、mail_log 表；sys_config 加 platform.base-url |
| `alter_presales_leader.sql` | sys_user_group 加 group_type 字段 |

> 注意：`alter_schedule.sql` 中张俊聪/戴海伟按用户名 `zhangjc`/`daihw` 匹配授权。若正式库用户名不同，请先确认实际用户名后修改 SQL 再执行；或执行后由管理员在"用户管理"手动分配"排期员"角色。

验证 SQL 生效：
```bash
PW=$(grep MYSQL_ROOT_PASSWORD .env | cut -d= -f2)
docker exec -i tp-mysql mysql -uroot -p"$PW" test_platform -e "
SHOW COLUMNS FROM test_application LIKE 'schedule%';
SHOW TABLES LIKE 'test_attachment';
SHOW TABLES LIKE 'mail%';
SHOW COLUMNS FROM sys_user_group LIKE 'group_type';
SELECT u.username,r.role_code FROM sys_user_role ur JOIN sys_user u ON ur.user_id=u.id JOIN sys_role r ON ur.role_id=r.id WHERE r.role_code='SCHEDULER';"
```
